# PinFlow — UI/UX Definition

Scope: the extension **popup** and the **toolbar badge**. PinFlow injects no UI
into web pages (PRD §25 "Non-intrusive"), so there are no in-page surfaces.

---

## Design direction

A small utility, not an application. The popup answers three questions instantly:
*is there a video? what can I do? did it work?* Calm, neutral, system-native.
No branding flourishes beyond a compact wordmark.

## Colors

Defined as CSS custom properties in `application/src/popup/popup.css`, with a
light theme and a dark theme via `prefers-color-scheme` plus `color-scheme: light dark`.

| Token | Light | Dark | Use |
| --- | --- | --- | --- |
| `--bg` | `#ffffff` | `#16181d` | Popup background |
| `--fg` | `#14161a` | `#f2f4f7` | Primary text |
| `--muted` | `#5b6472` | `#a3acba` | Secondary text, labels |
| `--line` | `#e4e7ec` | `#2b2f38` | Borders |
| `--raised` | `#f6f7f9` | `#1e2128` | Status panel, `kbd` |
| `--accent` | `#4f46e5` | `#7c74f2` | Primary button, focus ring |
| `--accent-hover` | `#4338ca` | `#8f88f5` | Button hover |
| `--accent-fg` | `#ffffff` | `#12131a` | Button label |

**State tones** (drive the status dot via `body[data-tone]`):

| Tone | Light | Dark | Meaning |
| --- | --- | --- | --- |
| `empty` / `idle` | `#8a93a0` | `#9aa3b0` | Nothing to do / unsupported |
| `ready` | `#2e7d32` | `#6bc57a` | Video detected |
| `pinned` | `#0b6bcb` | `#57a8f5` | Floating |
| `warn` | `#b26a00` | `#e0a341` | Not ready yet |
| `error` | `#c62828` | `#ef7b7b` | Failure |

**Toolbar badge:** `ON` on `#2E7D32` while pinned; `!` on `#C62828` on failure.

**Icon:** rounded tile, gradient `#4F46E5` → `#7C3AED`, white pin with a play
triangle punched out of its head. Sizes 16/32/48/128, generated by
`tools/generate-icons.mjs` (no text, so the mark needs no re-brand per locale).

## Typography

No web fonts — no network requests, instant render (PRD §24). Stack:
`"Segoe UI", system-ui, -apple-system, "Helvetica Neue", Arial, sans-serif`.
Base `13px` / line-height `1.45`. Wordmark `14px`, `700`, `letter-spacing: 3px`.
Body copy and detail text `12px`; footnote `11px`.

## Spacing

Panel padding `16px`. Status panel padding `12px`, radius `10px`. Button padding
`10px 12px`, radius `10px`. No spacing scale tokens — a fixed 11/12/14/16px
rhythm keeps the popup visually consistent.

## Components

| Component | Element | Notes |
| --- | --- | --- |
| Wordmark | `.brand__mark` + `<h1>` | Mark is CSS-drawn, `aria-hidden` |
| Tagline | `.brand__tagline` | "Keep it visible." |
| Status panel | `.status` | `aria-live="polite"` region |
| Status dot | `.status__dot` | Colour from the tone; `aria-hidden` |
| Status title/detail | `#status-title` / `#status-detail` | Detail hides when empty |
| Primary action | `<button id="action">` | One button, label swaps by state |
| Shortcut readout | `<kbd id="shortcut">` | Live value from `chrome.commands` |
| Privacy note | `.meta__note` | "Works locally. Nothing leaves your browser." |

## Navigation

None. The popup is a single screen with one action — deliberately no tabs,
menus, settings page or onboarding flow (PRD §28, §29).

## Screens

**Popup (the only screen).** Fixed width `300px`. Vertical order: wordmark →
tagline → status panel → optional action button → shortcut + privacy note.

## Layouts

Single column, centred wordmark, full-width button. The status panel and footer
are always present so the popup height stays stable between states — only the
detail line and the button appear/disappear. `[hidden]` is used rather than
removal so nothing shifts unexpectedly.

## Interactions

* **Pin Video** → injects the gesture-attributed payload; button disabled while
  busy; a `2.5s` safety timer ends the busy state if no result arrives.
* **Close PiP** → asks the page to leave PiP, then refreshes state.
* **Hover** → accent darkens on the button only.
* **Rapid clicks** → guarded by the busy flag; no duplicate requests.
  A repeated `pinVideo()` call is additionally harmless — the payload no-ops
  when PiP is already active.

## Loading/empty/error states

| State | Title | Detail | Action |
| --- | --- | --- | --- |
| Checking | "Checking for a video…" | — | none |
| Ready | "Video detected" | "Pin it to keep it visible while you work." | Pin Video |
| Not ready | "The video isn't ready yet." | "Try playing it first, then pin it." | Pin Video |
| Pinned | "Video is already pinned." | "It stays visible while you work in other tabs." | Close PiP |
| No video | "No supported video found." | "Open a supported video and try again." | none |
| Unsupported page | "PinFlow doesn't support this page yet." | "Currently supported: YouTube" | none |
| Unsupported site | "This website isn't supported yet." | "Currently supported: YouTube" | none |
| PiP unavailable | "Picture-in-Picture isn't available for this video." | "Your browser blocked the floating player for this video." | none |
| Rejected | "Couldn't pin this video." | "Try playing the video first and try again." | Pin Video |
| Unknown | "Something went wrong." | "Please try again." | Pin Video |

Never shown: stack traces, raw `DOMException` names, or internal codes such as
`pip-rejected`. A unit test asserts the copy contains neither "Error" nor any
internal code.

## Responsive behavior

Chrome extension popups are fixed-size; there are no responsive breakpoints. The
`300px` width is chosen so even the longest error detail line does not wrap
awkwardly or scroll horizontally. Touch input is out of scope (desktop browsers).

## Accessibility

Per PRD §33, verified against `popup.html`:

* A real `<button>` element — keyboard operable, never a clickable `<div>`.
* The action always carries **text**, never an icon alone (`📌 Pin Video`).
* The button's `aria-label` is reduced to plain text (the emoji is stripped) so
  screen readers announce "Pin Video", not the glyph.
* Status changes are announced through `aria-live="polite"`.
* `<main>` is labelled by the wordmark via `aria-labelledby="pinflow-title"`.
* Decorative elements (mark, dot) are `aria-hidden="true"`.
* Visible focus: `outline: 2px solid var(--accent); outline-offset: 2px`.
* `color-scheme` plus dark-mode tokens keep contrast sufficient in both themes.
* Error text is plain language, never an error code.

## Animations

Exactly one transition: the button's background colour, `120ms ease-in-out`,
wrapped in `@media (prefers-reduced-motion: no-preference)` so it is skipped
entirely for users who request reduced motion. There is no other motion.

## Platform-specific UI behavior

* **Brave (primary target)** — badge, popup and shortcut all use standard MV3
  APIs. Brave-internal pages (`brave://…`) are reported as unsupported rather
  than failing silently.
* **Other Chromium browsers** — identical rendering; only the shortcut
  configuration URL differs (`chrome://extensions/shortcuts`).
* **Unsupported pages** — `chrome.scripting.executeScript()` is rejected by the
  browser; the popup converts that rejection into the friendly unsupported state.
* **Toolbar feedback** — because no `notifications` permission is requested,
  shortcut failures are surfaced through the badge (`!`) and its hover tooltip.
* **Firefox** — out of scope, and no browser-sniffing code was added to fake it.
